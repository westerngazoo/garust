# garust — Invariants (INV-N catalog)

> The source of truth for what makes garust's `unsafe` code sound. Every
> `unsafe` block **and every `unsafe impl`** carries a `// SAFETY: INV-N`
> comment citing an entry below (rule G1 in `AGENTS.md`). When an invariant
> changes, every citing site is revisited in the same PR.
>
> Format inherited from Wari's `docs/invariants.md`. Each entry states the
> invariant, what relies on it, and the test that fails if it breaks.

---

## INV-1 · `Multivector` is layout-transparent over its coefficient store

> `Multivector<A, T>` is `#[repr(transparent)]` over its single field
> `coeffs: A::Blades<T>`. It therefore has exactly the size, alignment and
> padding of the store, and a `&[Multivector<A, T>]` is bit-for-bit a
> `&[A::Blades<T>]`.

**Relied on by:** the `bytemuck::Zeroable` and `bytemuck::Pod` impls in
`crates/garust-core/src/bytemuck_impls.rs` (feature `bytemuck`). Both impls
are bounded on the store (`A::Blades<T>: Zeroable` / `: Pod`), **not on
`T`**, so a custom [`BladeStore`] with padding or non-`Pod` contents simply
does not receive the impl. The standard stores are `[T; 2^N]` arrays, which
are `Pod` whenever `T` is.

**Guarded by:** the `const _` layout assertions next to the struct in
`crates/garust-core/src/multivector.rs` (size of `Pga3`/`Cga3` equals the
array's), and the `bytemuck_impls` tests (`multivector_round_trips_through_bytes`,
`slice_of_multivectors_casts_to_flat_scalars`, `zeroed_is_the_zero_multivector`).

**Would break if:** a second field were added to `Multivector`, or
`#[repr(transparent)]` were removed. The `const _` assertions fail to compile
in either case.

## INV-2 · Grade-typed newtypes are layout-transparent over one `Multivector`

> Every grade-typed newtype in `garust-geo` — `Motor<T>`, `Conformal<T>`,
> and every type generated by `pga_object!` / `cga_object!` (`Point`, `Line`,
> `Plane`, `Sphere`, …) — is `#[repr(transparent)]` over a single
> `Multivector` field. By INV-1 it therefore shares the layout of the
> underlying `[T; 16]` (PGA) or `[T; 32]` (CGA) array.

**Relied on by:** the `bytemuck::Zeroable` / `Pod` impls beside each type
(`motor.rs`, `conformal.rs`, the two macros in `pga.rs` and `cga.rs`). Each
impl is bounded on the wrapped multivector being `Zeroable` / `Pod`, which by
INV-1 reduces to the store and never to `T` alone.

**Guarded by:** the `const _` layout assertions beside each type (the macros
emit one per generated type), and the `bytemuck_tests` in
`crates/garust-geo/src/lib.rs` (`motor_round_trips_through_bytes`,
`object_buffers_cast_to_flat_scalars`).

**Would break if:** a newtype gained a second field (a cached norm, a flag),
or lost `#[repr(transparent)]`. The assertion for that type fails to compile.

## Adding an invariant

1. Write the entry here, in the PR that introduces the `unsafe`.
2. Cite it from the `// SAFETY:` comment as `INV-N`.
3. Name the test (or compile-time assertion) that fails if the invariant is
   violated. An invariant without a guard is a comment, not an invariant.
